# Carpenteria post-insertion reconfiguration — Stages 2–3


Backend operation `ProjectDocumentService.reconfigureEnclosure(nodeUuid, configuration)` and trusted IPC `project:reconfigure-enclosure` change one selected physical enclosure. Stage 2 starts at main `249305d`; Stage 3 adds its renderer entry point from main `1ef20cc`. Project format stays **10**, with no schema migration or manufacturer-specific runtime rule.

## Identity and scope

The target is an existing enclosure root UUID, never a quotation line or a catalogue ID alone. The request uses the existing generic `ConfigurationRequest`/resolver. Brand, model and physical depth/outer depth/usable depth must remain unchanged. Only axes whose effective stable value changes are checked for `editable_when_placed`; the saved interpretation and current model must both permit the change. Dependent/default choices count as changes too. Unchanged selections produce no write, split, repricing, dirty state or history entry.

For Q=1, the configured item and quotation line retain their IDs/UUIDs. For Q>1, ordinary snapshot duplication creates an independent Q=1 item/line, the original line becomes Q−1, and only the selected `prj_node.item_id` changes. No node is deleted, recreated, moved or repacked. Other physical units keep their original item association and identity; pooled units remain on the original line. The new configuration is independent even when an identical item already exists. Groups, user descriptions, line metadata and component commercial facts are copied from the selected configuration.

Preset relations are never instantiated or rebuilt. Existing panels/devices, their item snapshots and every stored position, designation and label are untouched. Calculated subtree coordinates are checked too: a configuration that would shift children is refused.

## Catalogue and provenance

All catalogue reads run in one read transaction, inside the shared project lifecycle IPC guard. The installed adapter descriptor remains the sole version authority. Known older/newer provenance anywhere in the affected subtree refuses with `project_engineering_stale`. Same-version different generations and unknown imported sources also require explicit project verification/refresh. A stale installed source instead requests catalogue reimport (`engineering_data_stale`).

The old enclosure configuration is resolved by the existing stable-code engineering refresh resolver, with unchanged linked BOM identity/contribution and matching saved engineering/context facts. This proves that reconfiguration is not silently refreshing the old interpretation or unlocking saved axes. Unknown legacy provenance alone does not refuse; it still needs this semantic proof. Open, display and Save never consult the catalogue.

## Commerce

Retained article identity is the linked portable `(brand, manufacturer code)`. Its existing product snapshot and per-unit sale price are reused, even when the current listino has changed or no longer supplies a price. A unique retained article with the same effective BOM role keeps its complete commercial row: customer discount, purchase discounts, cost, markup, lock and row ID (the copy's row ID for a split). Quantity and sequence are updated from the new resolution. The existing article/role discount policy applies when roles change: retain the article price, initialize the new role's commercial fields with ordinary insertion defaults.

New articles use current catalogue prices and the shared product-snapshot writer. It checks issuer/listino/date/price/multiplier identity against any project snapshot already present for that article. Conflicts refuse atomically with `price_snapshot_conflict`; no old snapshot is overwritten. Ambiguous retained commercial rows also refuse instead of choosing a price. A duplicate historical BOM can fail the earlier stable-BOM proof with `project_engineering_stale` (`bom_changed`); a retained article without a historical sale price refuses with `price_snapshot_conflict`. Physical-only configurations keep a null commercial total.

After updating BOM and primary references, the operation applies the existing quotation-removal `removeUnused` policy through the shared `removeUnusedProductSnapshots` helper. Candidates are the old BOM snapshots and the previous primary snapshot, including a primary reference absent from the old BOM. Only candidates with **no** reference from `prj_line.snapshot_id`, `prj_item_bom.snapshot_id` or `prj_item.primary_snapshot_id` are deleted. Other items and the Q>1 original configuration protect their snapshots. Cleanup remains inside the same atomic transaction and Undo/Redo restores it with the rest of the document; physical, derived-view, write or bookkeeping failure restores deleted snapshots too. This is reference cleanup, not general repricing or a document-wide purge.

Once an article's snapshot is unused and removed, reintroducing that article through reconfiguration or Catalogo uses the current listino. A→B→A therefore acquires a fresh price for the returning article, including across offline Save/Reopen. When another reference still retains the old snapshot, a conflicting current price continues to refuse atomically.

The item line's gross unit total is derived from the effective historical/current BOM prices, and its total matches its Q=1 quantity. Original Q−1 totals retain their saved unit price. Distinta derives article quantities from every line/BOM as before. Component/global discounts and labour continue through the existing commercial calculation. No general repricing operation is added.

## Validation and transaction

After proposed writes, `assessProjectPhysical` validates the **complete affected subtree** using the existing independent rule-family assessments: containment, classes, binding, exclusions, context, physical views, depth fit, capacities, slots, overlap and positioning. Global document invariants are checked too. Every incompatibility in the affected subtree refuses, including an existing unresolved incompatibility; unrelated subtrees do not acquire engineering updates. `incompatible_subtree` includes affected node UUIDs, rule codes and actionable messages. `position_changed`, locked axes, unsupported model/depth changes and catalogue/provenance failures have separate diagnostics.

One `recordAction` transaction includes item/line/BOM/snapshot writes, physical validation, derived-view construction, dirty/recovery bookkeeping and the history entry “Modifica carpenteria”. Failure rolls back the database and session history/state. Success does not save the file. Undo/Redo restore exact document images without catalogue access. Save and Save As retain history; reopen restores the portable result with no catalogue and starts a fresh history.

## Regression and real-source acceptance

`project-enclosure-reconfiguration.test.ts` covers Q=1/2/4, pooled quantities, selecting a second physical unit, an already-existing identical configuration, physical-only/unchanged options, retained/removed/quantity-changing components, historical/new prices, discounts/costs/locks, descendant failures, stale provenance, legacy verification, rollback after writes/view/bookkeeping, Undo/Redo and offline Save/Reopen. Review regressions cover A→B→A across listino change/offline persistence; subsequent Catalogo pricing; each protecting snapshot reference and Q>1 sharing; replaced primary cleanup; rollback after snapshot deletion; changed-role commercial defaults; duplicate/missing historical prices; new-source identity and all price provenance mismatches; aggregate monetary overflow; and exact descendant UUID/rule pairs for binding/exclusion diagnostics. Missing current prices request a priced listino; position-change diagnostics request compatible option choices.

`project-enclosure-reconfiguration-real-data.test.ts` requires `LIBREQUADRI_REV83_REAL_DB` pointing to an actual ready adapter-11 catalogue. It makes private SQLite copies, never changes the supplied catalogue, and checks all eight HDX 108 Frontale × Zoccolo blocks **311–318**, for Q=1 and Q=3. Each enclosure contains the source-compatible panel **853** and device **1777**. Commercial price changes are made only in the test copy; retained prices/discounts, fresh article prices, subtree identities/coordinates, resolved runtime drawing assets, history and offline persistence are checked. Both quantities also exercise an actual HDX door A→B→A with a retained plinth, offline Save/Reopen between changes, deleted unused door snapshots, a new listino for the returning door, and exact Undo/Redo/physical identity checks. `LIBREQUADRI_REV83_REAL_ASSETS` optionally supplies the associated assets root; otherwise it is the catalogue installation's sibling `assets/` folder.

UI remains outside Stage 2; its Stage 3 implementation is described below. Model/depth replacement, general splitting/reconfiguration of other physical kinds and general repricing remain unsupported. Alpha 0, installed user data and `.claude/` are untouched.

## Stage 3 — selected Carpenteria UI

Select a Carpenteria in Fronte Quadro or Albero fisico, then choose **Modifica carpenteria** in Proprietà. The standard modal uses the existing Progettazione `ConfigurationControls`, `ConfigurationResultPanel` and `ModelConfigurationSession`. It looks up exactly the saved brand/model code through `modelByCode`; there is no model picker, article preselection or replacement operation. Stable saved dimension/value codes restore parent-dependent options through the existing shared session. Saved visible selections stay displayed alongside the current resolver output. Missing or ambiguous saved selections block Apply and direct the user to explicit engineering verification.

Visible axes are disabled and labelled **Bloccato dopo il posizionamento** whenever the current model denies editability or the saved selection denies it. Enabled native selects keep the existing choice pruning and resolver behavior. The effective changes list compares saved stable values with the returned selections, including dependent/default changes and changes to hidden axes; it does not compute configuration rules. A dependent change to a locked axis remains visible and is subject to the backend's refusal, without silently restoring or overriding the resolver output.

For Q>1 the dialog explains that only the selected physical unit becomes an independent Q=1 configuration and the remaining units retain their selections. **Applica modifiche** sends one `project:reconfigure-enclosure` request using the selected **node UUID**, never the item/line identity. Both `complete` and `price_incomplete` previews may reach the backend: retained historical prices can be valid even when the current listino is missing them, while any unpriced new article is refused by the approved service. No UI preflight duplicates subtree, depth, provenance or price validation.

Backend error messages are shown in an atomic live alert in the fixed action footer, outside the independently scrolling configuration body. Electron's invocation prefix and known exception-name prefixes (including `EnclosureReconfigurationError`) are removed only at the start; the diagnostic text and affected UUIDs are retained. Long diagnostics have their own bounded, keyboard-focusable scrolling area beside the actions, so seeing a failed Apply never requires scrolling through configuration results. Failed requests keep the dialog and project selection available for correction/retry. Success adopts the returned complete project view through the existing shared callback. Drawing assets reload through the existing project-view effect; the same node UUID keeps selection, including after the Q>1 item split. Quotation, Distinta and history use that same returned view. A no-op is identified from the selected unit's configuration fingerprint, not the saved-file revision (which advances only on Save).

Native labels/selects/buttons, modal naming/description, initial focus on Annulla, the shared Tab trap and return-to-opener support keyboard and assistive interaction. The existing `useDialogFocus` infrastructure observes asynchronous control/child mutations and focus events. It remembers the focused select before Chromium can blur it on disabling, parks focus on the dialog while resolution is pending, and restores the same select when it becomes enabled again in the active modal. Waiting does not focus Annulla, so Enter cannot accidentally cancel during resolution. A deliberate focus move to another enabled control (Tab, Shift+Tab, click or `.focus()`) supersedes this restoration; the hook distinguishes its own repair from those focus moves. A removed select, covered/hidden modal or disposal clears the pending restoration. When Apply is disabled, the existing non-select fallback still chooses an enabled modal control or the focusable dialog if every control is disabled. Reenabled controls/new diagnostics after a refused submission retain modal focus and resume native Tab traversal without reviving an earlier select position. The document-level Tab boundary listener handles focus lost to the page; hidden or covered dialogs do not steal focus. Observers/listeners disconnect and pending restoration is cleared before focus returns to the opener; an already queued callback after disposal is ignored. Escape cancels while idle; Enter activates the focused button and repeated Enter cannot resubmit. Pending writes disable choices/actions and have a synchronous repeat guard. Document Undo/Redo and physical Delete/Escape shortcuts are blocked while editing; after completion they use the existing backend history. Save remains the ordinary explicit file workflow.

Disabled Apply has a visible status explanation in that same footer, linked to the button via `aria-describedby`. It distinguishes loading/resolving, failed resolution, missing/ambiguous saved choices, inactive/obsolete models, invalid or over-budget choices, incomplete required choices/BOM and absent physical profiles. The explanation and disabled gate use one presentation function. This does not weaken backend validation or alter the allowed complete/price-incomplete preview boundary.

`test/renderer/enclosure-configuration.test.tsx` covers action/scope presentation, saved choices, generic dependent/default resolution, current/saved axis locks and guarded callbacks, unchanged configuration, price-incomplete preview, missing/ambiguous choices, retry states and actionable errors. `test/renderer/enclosure-reconfiguration-real-data.test.tsx` connects the actual shared renderer session/submission to the approved backend using a ready HDX catalogue: Q=1/Q=3, selecting the second physical unit, no-op, new profile/vector output, refreshed selection/quotation/BOM, error atomicity, normal renderer Undo/Redo routing, unchanged saved bytes until Save, retained history across Save and offline reopen. The existing backend regressions continue covering stale engineering and incompatible descendants.

Review regressions additionally cover named/plain/nested IPC errors, the actual `EnclosureReconfigurationError` and complete diagnostic/UUID preservation, error placement outside the scrolling body, footer status/description links and guarded Apply for every unavailable state. `test/renderer/dialog-focus.test.ts` exercises the actual shared focus binding with native Node EventTarget and small platform doubles: select disable/re-enable with retained focus, body blur and body focusin before mutation delivery, including fast disable/re-enable in one delivery; deliberate Tab/Shift+Tab/other enabled-control focus during resolution (including before mutation delivery); close-before-completion and a queued callback after disposal; removed controls and covered/hidden pending dialogs; restore followed by asynchronous submission failure and keyboard recovery; no-enabled-control fallback, Tab/Shift+Tab and Escape; unchanged enabled focus and listener/observer cleanup. Existing renderer/modal tests run unchanged apart from the old source-string assertion tracking the shared binding. No jsdom or new testing framework is added.

These automated listener/interaction/markup tests do not execute Chromium or replace a live Electron keyboard and visual check. Remaining live checks: repeated native select disable/re-enable restores editing position, with no Annulla focus during resolution; native popup Escape and deliberate Tab/Shift+Tab/click during a delayed resolution prevent unwanted restoration; closing before completion preserves opener focus; Apply disabling while focused, then Tab/Shift+Tab/Escape through a refusal; footer/error visibility at minimum desktop size and zoom with long UUID diagnostics; and VoiceOver/NVDA announcements.
